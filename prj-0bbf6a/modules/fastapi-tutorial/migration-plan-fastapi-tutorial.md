## Module Explanation

The cookbook performs operations in the following order:

1. **default** (`cookbooks/fastapi-tutorial/recipes/default.rb`):
   - Installs seven system packages with one Chef `package` resource:
     - `python3`
     - `python3-pip`
     - `python3-venv`
     - `git`
     - `postgresql`
     - `postgresql-contrib`
     - `libpq-dev`
   - Creates `/opt/fastapi-tutorial` with mode `0755`.
   - Synchronizes the application source into `/opt/fastapi-tutorial` with one Chef `git` resource using action `sync`.
   - The repository URL, revision, branch, and checkout user are not exposed and must be obtained from the original cookbook or deployment variables.
   - Creates the Python virtual environment with:
     ```bash
     python3 -m venv /opt/fastapi-tutorial/venv
     ```
   - Installs Python dependencies with:
     ```bash
     /opt/fastapi-tutorial/venv/bin/pip install -r /opt/fastapi-tutorial/requirements.txt
     ```
   - Enables and starts the `postgresql` service.
   - Runs `execute[create_db_user]` as the PostgreSQL operating-system user and performs these operations in order:
     - Creates PostgreSQL user `fastapi`.
     - Assigns the hardcoded password `fastapi_password`.
     - Creates database `fastapi_db`.
     - Sets `fastapi` as the database owner.
     - Grants all privileges on `fastapi_db` to `fastapi`.
     - Suppresses command failures with `|| true`.
   - The Ansible implementation should use `community.postgresql.postgresql_user`, `community.postgresql.postgresql_db`, and `community.postgresql.postgresql_privs` for idempotence rather than reproducing `|| true`.
   - Creates `/opt/fastapi-tutorial/.env` with mode `0644` using inline content generated by the recipe.
   - The `.env` contents are not exposed and must be copied from the original recipe. Because it may contain credentials, mode `0600` is preferred unless exact Chef mode compatibility is required.
   - Creates `/etc/systemd/system/fastapi-tutorial.service` with mode `0644` using inline content generated by the recipe.
   - The unit’s `ExecStart`, user, working directory, environment handling, restart policy, and network binding are not exposed and must be copied from the original recipe.
   - Defines `execute[systemd_reload]` with command `systemctl daemon-reload` and action `nothing`.
   - The systemd reload runs only when notified by another resource; the supplied execution tree does not show an explicit notification relationship.
   - Enables and starts the `fastapi-tutorial` service after the unit is installed and systemd has been reloaded.
   - Iterations: None. No `.each` loops are present.

## Pre-flight checks

```bash
# Verify required packages
dpkg-query -W python3 python3-pip python3-venv git postgresql postgresql-contrib libpq-dev

# Verify application directory and virtual environment
test -d /opt/fastapi-tutorial
test -f /opt/fastapi-tutorial/requirements.txt
test -x /opt/fastapi-tutorial/venv/bin/python
test -x /opt/fastapi-tutorial/venv/bin/pip

# Verify the PostgreSQL instance individually
systemctl status postgresql
systemctl is-enabled postgresql
systemctl is-active postgresql
sudo -u postgres psql -tAc "SELECT usename FROM pg_catalog.pg_user WHERE usename = 'fastapi';"

# Verify the fastapi-tutorial database individually
sudo -u postgres psql -tAc \
  "SELECT datname, pg_get_userbyid(datdba) FROM pg_database WHERE datname = 'fastapi_db';"
sudo -u postgres psql -d fastapi_db -c "\l+ fastapi_db"
sudo -u postgres psql -d fastapi_db -c "SELECT current_database(), current_user;"

# Verify application credentials without exposing the password
PGPASSWORD='<vaulted-fastapi-password>' \
psql -h 127.0.0.1 -U fastapi -d fastapi_db -c "SELECT 1;"

# Verify Python dependencies
/opt/fastapi-tutorial/venv/bin/pip check
/opt/fastapi-tutorial/venv/bin/pip list

# Verify the environment file without printing secret values
ls -l /opt/fastapi-tutorial/.env
sed -n 's/^\([^=]*\)=.*/\1=<redacted>/p' /opt/fastapi-tutorial/.env

# Verify the fastapi-tutorial service individually
systemctl cat fastapi-tutorial
systemctl status fastapi-tutorial
systemctl is-enabled fastapi-tutorial
systemctl is-active fastapi-tutorial
systemctl show fastapi-tutorial \
  --property=LoadState,ActiveState,SubState,ExecMainStartTimestamp

# Verify service logs individually
journalctl -u postgresql --no-pager -n 100
journalctl -u fastapi-tutorial --no-pager -n 100

# Identify actual listening ports before running targeted checks
ss -ltnp
```
